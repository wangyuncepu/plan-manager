## 摩擦点（按优先级）

### P1 — 设计级
1. **双角色墙 × 文件隔离墙 在跨项目/元任务处冲突**〔真bug级设计缺口〕
   - 场景：以 executor 跑 PLA-015 去管理 YeBoZhai，下一步"为 YEB-001 起草计划"是 strategist 专属；且写入 YeBoZhai（.project/任务）属跨项目越界，严格需 write-exception/暂停确认。
   - 影响：管理"另一个项目"的任务无法在单一角色内顺畅完成；元/编排型用法别扭。
   - 建议：为"管理外部项目"提供显式授权范围（计划级 project-scope write-exception），或允许 strategist 起草+executor 执行的组合在一个被批准计划内连续进行。

2. **跨项目写入无工具级护栏，仅靠 AI 自律**〔体验/安全〕
   - 场景：PLA-015 执行时写了 YeBoZhai/.project 与新任务，脚本未要求 write-exception 确认。
   - 影响：文件隔离是"文档约定"，非强制；不同 AI 执行可能越界。
   - 建议：执行写操作落到"非当前任务目录"时，脚本或流程给出显式确认/记录。

### P2 — 体验级
3. **注册既有内容项目体验粗糙**〔体验〕
   - 场景：YeBoZhai 已有丰富素材+历史会话，目标完全可推断；标准流程仍倾向从零问目标。
   - 建议：检测到目录已有内容/会话时，自动从素材提议目标让用户确认（本次已手动这么做，应内建）。

4. **create 对既有项目自动塞 README.md**〔体验/可能bug〕
   - 场景：注册已有 .md 内容的项目，create 仍生成 README.md。
   - 影响：对既有项目可能多余/意外多一个文件。
   - 建议：已有内容时跳过自动 README，或询问。

5. **create dry-run 不提示目录已存在/将就地注册**〔体验〕
   - 场景：对已有目录 dry-run，仅显示"create at <path>"，无"目录已有 N 文件、将就地注册"提示。
   - 建议：dry-run 显式区分"新建空目录" vs "注册既有内容目录"。

### P3 — 细节
6. **slug 去前导下划线**〔细节〕：`_x` 任务目录变 `x`，与输入名不完全一致（早前 _pla014 已见）。建议 slug 规则文档化或保留。
7. **任务 ID 前缀按项目派生**〔细节〕：YeBoZhai→YEB-001；早前 PLS/PLA 前缀漂移说明派生逻辑会让人意外。建议注册时展示将用前缀。

## Top 3 改进建议
1. **解决双角色×隔离在跨项目管理处的冲突**（P1#1）—— 这是阻碍"用它管真实项目"的最大体验障碍。
2. **跨任务目录写入加显式护栏/确认**（P1#2）—— 把隔离从约定变约束。
3. **"注册既有项目"专属流程**：自动提议目标 + 跳过/询问 README + dry-run 区分（合并 #3/#4/#5）。

## 结论
核心闭环真实可用、安全（既有数据零改动）。最该投入的不是新功能，而是**打磨"管理既有/外部项目"的体验与护栏** —— 与项目前提"反馈>功能、减少交互"一致。
